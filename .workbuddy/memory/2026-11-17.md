## 排查 pnpm tauri dev "运行失败"

- 复现结论：本机 `pnpm tauri dev` 可正常跑到 `Running target/debug/app`，窗口能起；二进制单独运行 60s 稳定不退出。Rust 编译 1m27s 通过。
- 无法复现用户的失败，怀疑环境差异。已做的加固：`tauri.conf.json` 的 `beforeDevCommand`/`beforeBuildCommand` 从 `vp dev`/`vp build` 改为 `pnpm dev`/`pnpm build`，避免全局 vp 不在 PATH（IDE 终端常见）时 beforeDevCommand 失败。
- 待用户提供实际报错文本再定位。常见三类：端口 5173 被占用、`vp` 找不到、first-run Rust 编译超时/中断。

### 结论：端口 5173 冲突（已修复）

- 用户确认报错为端口 5173 被占用。根因：`pnpm dev`(5173) 与 `pnpm tauri dev` 的 beforeDevCommand 抢同一端口，`strictPort: true` 下 Vite 直接退出，beforeDevCommand 失败导致 tauri dev 中止。
- 修复方案：桌面端独立端口 1420（Tauri 官方模板惯例）。新增 `dev:desktop` 脚本 = `vp dev --port 1420 --strictPort`；tauri.conf 的 devUrl 改 1420、beforeDevCommand 改 `pnpm dev:desktop`。已实测 5173 与 1420 可同时运行。
- 注意：用 Bash 工具起的后台进程会随工具调用结束被回收，不能靠它做「常驻」验证。

- 需求：托盘常驻、关窗隐藏不退出、托盘弹窗展示最近项目、点击项目用对应工具打开、弹窗底部设置/退出。
- Rust 新模块：config.rs（Tool/Project 模型 + JSON 原子持久化 + 损坏回退）、opener.rs（spawn → 登录 shell `command -v` 探测 → open -a 三级降级）、tray.rs（托盘创建/弹窗定位/toggle/blur 隐藏）、commands.rs（7 个命令，配置变更返回全量快照 + 广播 config-changed）。
- 关键决策：弹窗窗口启动时创建一次（label=tray, visible=false）永不销毁；关闭事件一律 prevent_close + hide；blur 隐藏后 300ms 内的托盘点击视为关闭意图（防 blur→click 抖动）；show 后 400ms 内的 blur 视为假失焦；定位用 monitor_from_point + clamp。
- 前端：tray.html 独立入口（vite rollupOptions 多入口）+ src/tray/TrayPopup.vue + src/api/desktop.ts；设置页 /settings 管理项目。
- 测试抓到真 bug：`open -a` 用 spawn() 判断成功与否是错的（应用不存在时 open 仍启动成功），改为 output() 检查退出码。
- 经验：Edge headless=new 在 macOS 上布局视口最小 492，截图 window-size=380 会被裁切，视觉验证小窗口页面要用大视口截图或别信截图裁边。
