## 多显示器托盘弹窗定位修复（重要）

- 症状：点击 B 屏托盘，弹窗在 A 屏出现。根因：TrayIconEvent rect 是物理坐标（乘了托盘屏 backingScaleFactor），tao 的 monitor_from_point 按 CGDisplayBounds（全局点空间）匹配；缩放>1 的屏上物理坐标在点空间越界 → 匹配失败 → 回退主屏。
- 深层：tao Monitor::position()/size() = CG点×本屏缩放，混合 DPI 下各屏物理空间不统一，物理坐标直接夹紧也不可靠。
- 修复（tray.rs position_near_tray）：macOS 分支遍历 available_monitors，用各屏自己的 scale 还原 CG 点边界（position/scale），图标物理坐标÷该屏 scale 落进哪块屏的点边界即命中；定位全程点空间，set_position 传 LogicalPosition（tao 对 Logical 变体原样透传 NSWindow，不受窗口当前屏 scale 二次换算影响）。非 macOS 保持 monitor_from_point + PhysicalPosition。clamp 换 max→min 防极小屏 panic。

## 多显示器修复第二轮：NSStatusItem 权威定位（最终方案）

- 第一轮几何推算实测无效：A 屏 Retina 1512×982@2x 物理 x∈[0,3024)、B 屖 1920×1080@1x 物理 x∈[1512,3432)——**物理区间重叠**，任何基于事件 rect 的几何匹配在混合缩放下都无唯一解。
- 新方案（tray.rs）：`TrayIcon::with_inner_tray_icon` → tray-icon `ns_status_item()` → NSStatusBarButton（into_super×3 到 NSView）→ `.window()` → NSWindow（frame=图标全局矩形，Cocoa 下左原点点坐标）+ `.screen()`（权威 NSScreen 归属）→ visibleFrame 夹紧边界；Y 轴翻转常数 `CGDisplayPixelsHigh(CGMainDisplayID())` 与 tao window_position 完全一致。
- **死锁排查结论（关键）**：tray 回调在主线程事件循环派发中；`run_item_main_thread!` 宏会 run_on_main_thread + rx.recv() 阻塞，看似必死锁，但 tauri-runtime-wry `send_user_message` 检测当前线程 == main_thread_id 时**同步执行**闭包不走 proxy，recv 立即返回，无死锁（src/lib.rs tray plugin 与 shortcut 两条路径均安全）。Retained 非 Send，所有 ObjC 计算在闭包内完成只返回 f64。
- objc2 依赖加入 src-tauri Cargo.toml（macOS target）：objc2 0.6 / objc2-app-kit 0.3.2（NSStatusBar/NSStatusItem/NSStatusBarButton/NSButton/NSControl/NSCell/NSResponder/NSView/NSWindow/NSScreen）/ objc2-core-graphics 0.3.2（feature 是 **CGDirectDisplay** 不是 CGDisplayPixelsHigh）/ objc2-foundation（NSThread，MainThreadMarker）；`NSStatusItem::button(mtm)` 需传 MainThreadMarker。
- toggle_popup/position_near_tray 签名加 `tray: &TrayIcon` 参数；shortcut.rs on_trigger 改用 tray_by_id(tray::TRAY_ID) 借引用传入。几何推算保留为 macOS 兜底 + 非 macOS 主路径（统一抽成 TrayPlacement 结构）。
- 需求 #25：SettingsView 已配置项目列表图标从写死 folder-git-2 改为随 toolId 显示对应工具图标（tools 自带 icon 字段；TrayPopup 原本就已按工具区分）。
